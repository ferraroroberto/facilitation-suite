# Results and exports

The **Results** tab reads the session folder, so it works on any session once it has run (live or not): every captured activity in the order it happened, and for the selected one the visual exactly as the stage showed it at the stop, its top items (words, votes, countries) and every answer with the person's name and chat time — hidden ones struck through.

Each **quiz game** is a row too, labelled by its quiz name and run (a replay with `quiz_new_game` is run 2): its podium, the final leaderboard (rank, nickname, score, correct answers, average response time, source *phone* or *chat*) and, per question asked, how many picked each answer with the correct one(s) marked. Everything is derived by replaying `live/quiz.jsonl` through the game engine (`src/quiz/results.py`), so the numbers are the ones the stage showed. Kicked players are left out; a lobby nobody joined is not a game.

- **Export session PDF** — `exports/session.pdf`: every slide at its first showing and each live result where its capture last started (the page order is the order the session ran in, not the plan's), in the order of `live/events.jsonl`, one widescreen page each, then an appendix that opens with the *Participation* table — a row per person, a column per activity (by number, the titles in a legend above), their answers in total, in the *Early* and in the *Late* half of the session, and their chat messages; a zero shows as `–` — followed by every counted answer. The first half of the activities, the odd one out included, is early (`Early (1–4)`, `Late (5–8)`); the table is left out when nobody answered. Printed by headless Chromium in its own process. A capture whose image never rendered still gets a page saying so. A quiz adds a page per question asked (when it was asked: its distribution, or its frozen image if one exists) and a podium page per game (when the podium was shown, else right after its last question), and each game's leaderboard in the appendix.
- **Excel report** — `exports/report.xlsx`: a summary, one sheet per activity (name, time, answer, parsed value, hidden), two sheets per quiz game — `Quiz – <name>` (leaderboard, then each question's answers and how many picked them) and `Quiz – <name> answers` (every player × question: answer, correct, points, response ms), with ` run <n>` for a replay — and *Participation* (per person: answers per activity, total, the same *Early* and *Late* counts as the PDF's table, chat messages — most active first; both outputs read one shared table, so their numbers agree). A session without a quiz gets exactly the same report as before.
- **Check against Zoom's saved chat** — pick the `meeting_saved_chat.txt` Zoom saved when the meeting ended (the picker opens in `Documents\Zoom`). The banner says how many of Zoom's messages the app has ("412 of 412 matched") and lists any missing, plus any only in the app. Reactions and simulated messages are not counted; emoji the reader cannot see and your own "You" messages still match. The report is kept in `exports/zoom-reconciliation.json`.

## One person under several names

Zoom's chat shows only a display name, so a rename mid-session, a short name and a second device ("iPhone de Ana") read as different people. The **People under several names** card on the Results tab lists likely groups; **Merge** accepts one, and *Merge by hand* joins any two names. Nothing merges without that click.

A suggestion compares names without case, accents or punctuation, after dropping a device prefix or suffix (`iPhone de `, `iPad de `, `Galaxy de `, `<name>'s iPhone`). Equal names are one person; a name that is the start of another ("Ana" for "Ana Perez"), or its first word plus an initial ("Ana P"), joins it, unless it could be two different people. A roster `name` is the preferred canonical name of its group. A merge is saved as `aliases.yaml` in the session folder (`{canonical: [alias, ...]}`, plain text, hand-editable, never committed); *Undo* removes it, and deleting the file restores the raw view.

Results count the canonical name wherever they count people: each activity's people, the answer rows (shown as `Ana Perez (as iPhone de Ana)`), *Participation* and the exports, and a scale or map is recounted so a person who voted under two names counts once, by their latest answer. `chat.jsonl` and the live stage keep the raw names. Quiz players are keyed by name when they join, so a quiz is not merged.
