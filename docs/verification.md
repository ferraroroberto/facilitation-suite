The pre-ship gate is `& .\scripts\verify-before-ship.ps1`: personal-data guard → byte-compile → ruff → static ratchet (no new duplicate block, unused import/variable, or ruff bug (`B`) or security (`S`) finding beyond `.static-ratchet-baseline.json`; a wrong finding keeps a `# windows-only-exempt: <reason>` marker) → pytest → diff-routed Playwright e2e against a disposable instance.

**Under an `AllSigned` execution policy** the gate file itself cannot be started with `&` or `-File`, so it runs as `& .\.venv\Scripts\python.exe -m src.ps_script scripts\verify-before-ship.ps1`: `src/ps_script.py` reads the effective policy and, under `AllSigned` or `Restricted`, loads the script as a ScriptBlock (the policy stays as the machine set it, nothing is signed). The gate loads its one nested script, `box_lock_gate.ps1`, the same way, and `tray.bat` runs the shared tray helper as a ScriptBlock too. `tests/gate/test_portability.py` starts each under a process-scope `AllSigned`.

**Verdict line.** The last stdout line of a gate run is `GATE-RESULT: PASS` or `GATE-RESULT: FAIL`, on every path that can still run code, with exit codes unchanged (0 pass, 1 anything else). Never pipe the gate when its exit code matters (`... | tail` reports `tail`'s status); a caller that cannot avoid a pipe asserts on that line, and a run without one is not a pass. `tests/gate/test_gate_result.py` covers a pass, a failed stage, an early terminating error and a missing `.venv`.

**Loopback port pool.** Every closed TCP connection to a local server leaves an (ephemeral port, server port) pair in TIME_WAIT for minutes, and Windows fails a `connect()` that lands on one with `net::ERR_ADDRESS_IN_USE`, so a gate that opens many connections, or runs beside another lane's gate, can fail a page load that has nothing wrong with it. The harness keeps its own share of that churn down: `tests/e2e/_shared_context.py` leases browser contexts by their arguments, so `page`'s context and every story's own `browser.new_context(**args)` (the stage window, the phones) are reused across tests, and `context.close()` on one resets it (pages, routes, cookies, permissions and local storage on each origin, through a routed scratch page that opens no socket) and hands it back; the boot poll in `tests/e2e/conftest.py` reuses one keep-alive connection. A story that sets context-level state the reset cannot undo (init scripts, extra headers, offline, geolocation, the page clock) fails `tests/e2e_harness/test_shared_context.py`. `tests/e2e/_port_pool.py` names the failure that remains: a report carrying `ERR_ADDRESS_IN_USE` (or Playwright's Node-side `connect ENOBUFS`) leads with `PORT POOL EXHAUSTED`, and the run ends with a section of that name listing the tests, which means wait a few minutes and re-run, not debug the page. The dynamic port range and `TcpTimedWaitDelay` are machine-level and stay untouched. To measure a change, sample `netstat -ano -p tcp` every 0.5 s through one full e2e run and count the new loopback TIME_WAIT pairs whose server end is a port the run itself listens on (the disposable app, the quiz player, the fake hub); on one host a full run went from about 310 to about 235 such pairs, and from about 205 to about 135 on the app's own port. What remains is mostly the page connections a story opens and closes, the server's 5 s idle keep-alive, and the two disposable servers the product's own replay and PDF renderers start (about 38 pairs each in the results story).

**Design inventory.** Each e2e story calls `surface(page, "<tab>.<surface>")` (the vendored `tests/e2e/_surface.py`) once the surface is open, at the first test that opens it. It does nothing unless `DESIGN_SURFACE_CAPTURE` is set, which fleet-config's `/design-review measure facilitation-suite --e2e` does against `scripts/design_review_synthetic.py` (the suite's own disposable instance, never the live app). A new tab, sheet or dialog joins the inventory by adding one call to the test that opens it; the stage is never tagged, since it follows the session theme.

**Mac nightly.** The `[ci.nightly]` table in `.fleet.toml` enrols the repo in the fleet's Mac Mini nightly (project-scaffolding's Mac runner doc holds the schema): the unit suite on a clean `.venv`, the e2e suite on Playwright WebKit and a Mobile Safari smoke of `/` on an iPhone simulator. It checks what landed on `main` and never gates a merge. A test that needs Windows desktop or filesystem behaviour (the MSAA chat reader, a file held open across a log rotation, OneDrive file attributes, a port rebind straight after close) carries `@pytest.mark.windows_only`, and one that drives headless Chromium (the session PDF, the frozen capture PNGs) carries `@pytest.mark.needs_chromium`, because the Mac installs WebKit only; the nightly's unit leg deselects both, the WebKit e2e leg skips a `needs_chromium` story through `tests/e2e/conftest.py`, and the local gate still runs them.

**Verify skill.** `.claude/skills/verify-facilitation-suite/` (scope: this repo's root) launches a disposable instance, drives every mapped feature in a real browser and cleans up; the feature map is generated from the `surface()` calls, never hand-written. Claude Code loads it from there. Codex and Pi read `.agents/skills/`, so link it per checkout (the link is gitignored, as is the rest of `.agents/`; skip it if the path already exists):

```powershell
New-Item -ItemType Directory -Path .agents/skills -Force | Out-Null
New-Item -ItemType Junction -Path .agents/skills/verify-facilitation-suite -Target (Resolve-Path .claude/skills/verify-facilitation-suite).Path
```

After adding or renaming a `surface()` call, run the skill's Maintain section; its static half reports a stale map.
