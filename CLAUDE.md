## This repository

One local app for running a live online workshop: a **stage** (full-screen on the display OBS captures), a **presenter** cockpit (second monitor), Zoom-chat-driven activities read locally through Windows accessibility (no bot), breakout groups, per-item timers and session results. FastAPI + vanilla JS + pystray tray, port **8449**. The epic issue (#1) is the design; each build step is a sub-issue ("Step N/14").

**Project specifics:**

- **Stack is fixed:** Python 3.14 (`py -m venv .venv`; invoke `& .\.venv\Scripts\python.exe`, never activate), FastAPI served by the vendored `app/webapp/serve.py` (hypercorn, HTTP/2 over the cert; `"server": "uvicorn"` in `config.json` is the HTTP/1.1 fallback; selector loop), Pydantic v2, PyYAML, vanilla JS ES modules (no bundler), pystray. Windows-first: PowerPoint COM import and the MSAA chat reader need Windows + PowerPoint + Zoom desktop.
- **Public repo, personal project.** No client, cohort, participant or employer names anywhere — code, docs, issues, commits, screenshots, fixtures. Synthetic data only (`tests/fixtures/`).
- **Personal data never gets committed.** Sessions live in their own folders **outside** the repo (default under OneDrive, `config.session_root`). The ledger `sessions.local.yaml`, `config/config.json`, `data/`, `.env`, any `.xlsx`/`.pptx`/`.docx`, `session.yaml`, a session's `aliases.yaml`, `playbook.md` and `notes.md`, `chat.jsonl`/`events.jsonl`/`quiz.jsonl`/`room.jsonl`/`transcript.jsonl`/`hints.jsonl` and the copilot's `*.wav` outside `tests/fixtures/` are gitignored and refused by the gate's personal-data guard. Run `git status` before every commit.
- **No database inside OneDrive.** Session data is plain files: `session.yaml` + append-only JSONL. Anything cache-like goes under the repo's gitignored `data/`.
- **UX surface map:** `docs/ux-surfaces.yaml` is the one source listing every surface a person can reach (tab, card, sheet, dialog, menu, Settings group, cockpit card, stage rendering, remote and player screen); `docs/ux-surface-map.md` is generated from it with `& .\.venv\Scripts\python.exe scripts\ux_surface_map.py` and never edited by hand. A change that adds, removes, renames or reshapes a surface updates its entry in the same change, adds or removes the matching constant `data-surface` on its root, and regenerates the page. The generic builders in `static/js/dialogs.js` stamp one id per kind (`dialog.form`, `dialog.confirm`, `dialog.row-menu`), a caller's own dialog is an entry with `root: none`, and a sheet is stamped by its caller. Convention: project-scaffolding's `docs/ux-surface-map.md`.
- **Visual identity:** the app and the presenter follow the fleet design (`~/.claude/design.md` + `design.dark.md`): tokens in `app/webapp/static/css/tokens.css`, components vendored byte-for-byte from `project-scaffolding` into `app/webapp/static/_vendored/` and recorded in `.fleet.toml [vendored]` — never edit a vendored file. The Lucide sprite is `static/sprite.html`, built by `scripts/build_sprite.py` and inlined into every page at `<!--SPRITE-->`. **The stage does not** follow the fleet design: it follows the session theme (`assets/themes/*.css`), background `#F2F2F2` to match the slides.
- **Env overrides** (tests and the e2e instance use them): `FS_CONFIG_PATH`, `FS_LEDGER_PATH`, `FS_DATA_DIR`, `FS_ENV_PATH` (the `.env` holding the Spotify login).
- **Verification — the pre-ship gate is `& .\scripts\verify-before-ship.ps1`** (the stages in order: [`docs/verification.md`](docs/verification.md)). Each ratchet is a vendored `scripts/<name>_ratchet.py` with a `.fleet.toml [<name>_ratchet]` table and a `.<name>-ratchet-baseline.json`; each reads the whole tree, so it is never path-routed, and its exit 3 (a detector could not run, git unusable, a file unreadable or unparseable) fails as NOT CONFIRMED, never a pass or a skip. The docs, static and comment gates are called through `python -m scripts.<name>_ratchet_gate`; the others run the script directly. Shrink any of the thirteen baselines in the PR that removes debt (`--update-baseline`); adding to one needs `--allow-additions` and shows in review. Per ratchet:
  - **docs** — fails when `README.md` passes 40 KiB or `README.md` / `docs/**/*.md` gain a history marker (issue reference, dated heading, changelog heading); the baseline is empty, so any new marker is a failure.
  - **static** — fails on a duplicate block (jscpd via `npx`, so **Node is a prerequisite**), an unused import/variable (ruff `F401,F841`), or a ruff bug (`B`) or security (`S`) finding (`S113` strict) that is not in the baseline.
  - **comment** — fails when a file's count of `#NNN` issue references inside comments rises beyond the baseline (a comment states the present-tense why; history lives in git, PRs and issues).
  - **structure** — fails on a new oversized file, function or directory, on a baselined offender that grows, and on a root folder `.fleet.toml` does not declare; where new code goes: [`docs/layout.md`](docs/layout.md).
  - **instruction** — fails when an instruction file (`CLAUDE.md`, `AGENTS.md`, a skill) gains a hit of the weekly prompt audit's deterministic rules or passes its size cap.
  - **doc-refs** — baseline empty; fails on a doc naming a path, module, link or loopback port that does not exist; ports of other services are listed in `allow_refs`.
  - **dead-code** — baseline empty; fails when a function, class or method is defined and nothing in the tracked Python tree reads its name; route handlers, tests and decorated framework hooks are never reported, and `[vendored]` destinations are read for references but not reported, so declare a new vendored Python file there first.
  - **conventions** — fails when a file's count of hits for an enabled rule rises beyond the baseline: `no-window` (a `subprocess` spawn without `creationflags=`), `logging-not-print` (a `print` in `app/` or `src/` library code), `no-drive-path` (a hardcoded drive-letter path literal) and `subprocess-timeout` (a blocking `subprocess.run`/`call`/`check_*` with no `timeout=`) and `host-identity` (a test that reads this machine's own identity, not the vendored `synthetic_host` fixture); `secret-compare` and `git-wrapper` stay off because the repo has no helper for either. A hit that must stay stays exempt behind its own `# <rule>-exempt: <reason>` comment.
  - **runtime-write** — its own baseline, empty; this one flags `src/write_target.py` resolving a write under a code folder, or a stray file left there once a test run finishes; an unresolvable target must go through `outside_code`, else the exempt comment names the reason.
  - **usage-track** — its own baseline too, also empty; counts, per file, untracked controls, untracked sheets and dynamic ids, and separately confirms the usage log is wired (`[vendored]` lists `usage-log`/`usage_log`, a file calls `initUsageLog(`, a tracked Python module calls `usage_router(`); the same escape hatch covers a single flagged hit.
  - **ux-surface** — baseline empty; fails on a surface root (a `<dialog>`, a `dialog`/`menu`/`tabpanel` role, a popover) without a constant `data-surface` id, an id with no entry in `docs/ux-surfaces.yaml`, an entry that names a root no element carries, one id on two roots, a link to a missing entry, or a `docs/ux-surface-map.md` that is not what `scripts/ux_surface_map.py` generates from the map; it scans the app, presenter, remote, stage and the quiz player's HTML and JS.
  - **request-budget** — its own baseline, recorded at adoption and only ever shrunk; per file it counts the rules `fixed-rate-poll`, `poll-floor`, `unwatched-loop` (a loop that runs while nobody views must be declared in `.fleet.toml [[request_budget.loops]]`), `scan-per-request` (handlers under `app/webapp/routers`), `default-pool` and `timing-middleware`; a hit that must stay keeps a `# request-budget-exempt: <reason>` marker, and moving a poll onto the vendored `poll` helper is how its count falls.
  - **windows-only** — baseline empty; fails when a test that touches a Windows-only API lacks the `windows_only` marker the Mac nightly filters on: an import of `winreg`/`win32*`/`pythoncom`, `subprocess.CREATE_NO_WINDOW`, `ctypes.windll`, `os.startfile`, a Windows-only environment variable read (`ProgramFiles`, `LOCALAPPDATA`...) nothing in the file sets, or a planted `.exe` under a fake install folder; a wrong finding keeps a `# windows-only-exempt: <reason>` marker.

  The e2e phase boots its own disposable webapp on a free port with temp config/ledger/data; it never touches the live `:8449`. The e2e stories write (Settings, sessions, simulated chat), so there is no live mode: setting `FS_E2E_LIVE` makes the suite exit instead of running. Keep the e2e suite under 15 collected tests. **Runtime contract (measured 2026-10-03, #165):** 14 nodes, one chromium projection; the e2e phase takes about 47–50 s (the first node boots the disposable app in about 3 s; a cold first run after a reboot has cost 15 s more), unit pytest about 2 m 20 s, the whole gate about 3½ min on a `full` tier and about 2½ min when e2e is routed `skip`. **Routing:** `.fleet.toml [e2e]` sends any `src/` change to `full` (the app imports `src/`, #171), so only `tests/` unit files, `scripts/`, `docs/` and other prose skip the browser leg. The e2e phase writes `data/e2e-junit.xml` (`[e2e] junit_xml`), the record `/e2e-audit` reads its timing from; a number here that is more than 25 % off a quiet run is stale.
- **Restart recipe (long-lived process, no hot-reload):** after the gate passes, run the one command `.\.venv\Scripts\python.exe -m src.restart_check restart --port 8449` (`./.venv/Scripts/python.exe` in Git Bash; same in every shell). It runs this checkout's `tray.bat --restart` by absolute path and exits non-zero unless a different process serves `HEAD`. Never type the bare `tray.bat --restart`: it is not found from any shell here (by hand only `.\tray.bat` in PowerShell, `./tray.bat` in Git Bash), and Git Bash `cmd.exe /c "tray.bat --restart"` exits 0 having restarted nothing. The bat runs the shared `%USERPROFILE%\.claude\tray\tray_lifecycle.ps1` (kills the tray subtree, reclaims `:8449` by PID scoped to this repo's `.venv`, starts fresh; without that helper `tray.bat --restart` takes its standalone path, `scripts/standalone_restart.py`, which ends only the processes whose command line is under this repo's `.venv` and that are the tray or own a configured port, never a name match, then starts and verifies `/api/version` the same way, so `--restart` works with or without the helper). Backgrounded, `Start-Process`, or `cmd /c` launches have silently done nothing several times — always run it foreground and read its own result. **Build-identity check: `GET https://127.0.0.1:8449/api/version` → `git_sha == git rev-parse --short HEAD`** (`:8449` serves HTTPS via a tailnet cert; use `-k`/no-verify), polled bounded (≤30 s). The chat reader runs as its own process under the tray (step 6) and restarts with it.

## CI expectations

- **The `ci` workflow is switched off** (`disabled_manually` on GitHub): a PR or a push to `main` starts no run, so the local gate (`scripts/verify-before-ship.ps1`) is the only check and the contract. Do not re-enable it without Roberto's say; a green CI run is not part of done.
- `.github/workflows/ci.yml` is kept, job `gate`, so the repo can be switched back on: a fresh `.venv` from `requirements.txt` on a clean machine, the unit suite (`pytest --ignore=tests/e2e`) and the e2e suite on one desktop chromium leg (no phone/WebKit leg: the phone viewport is emulated inside chromium by the tests that need it). It does not run ruff, byte-compile or the personal-data guard. The one test that drives real PowerPoint COM skips itself unless `FS_TEST_POWERPOINT=1`.
- Hosted-runner timing is the e2e suite's weak spot (about 3x slower than this machine), so an e2e step waits for an explicit state, such as a card being open, before it acts, instead of trusting that a click has landed.
